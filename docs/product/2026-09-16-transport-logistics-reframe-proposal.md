# 交通・物流の分類、出典、画面構成の見直し案

2026-09-16。状態：ユーザーの「designも構造も直してみてください」を受け、下記の初期範囲をローカル実装・検証。公開画面へのデプロイは未実施。

## 目的

一般の人が「自分の地域は、どこへ、何でつながっているか」「人や物を運ぶ道にはどんな役割があるか」を地図から発見できるようにする。全国の高速道路・新幹線・鉄道・航空・海運を対象候補にする。

全国の運行監視、経路検索、到着予測を初期画面の前提にしない。データの裏付けがあるつながりと、その意味を説明する。

## 分類は独立した軸にする

利用者には馴染みのある「高速道路 / 新幹線 / 鉄道 / 航空 / 海運」を入口として見せる。内部の意味は次のように整理する。

| 軸 | 定義と候補 | 表示への対応 |
|---|---|---|
| 運ぶ対象 | passenger / freight。両方を扱うサービスは両方に関連付ける | 人の移動 / 物の輸送 |
| 輸送手段 | road / rail / air / sea | 道路・鉄道・航空・海運の記号と線種 |
| サービス種別 | 高速道路、新幹線、在来線旅客、貨物鉄道、旅客便、航空貨物、フェリー、RORO、内航貨物など | 見たい交通手段を絞り込む |
| 地理的範囲 | domestic / international | 国内を初期値にする。内航と外航を区別する |
| 知りたいこと | infrastructure / scheduled-connection / observed-flow / operation-event | 路線と拠点 / 就航・運行上の接続 / 輸送実績 / 運行状況 |
| 根拠と時点 | geometry source / service source / statistics source / status source、それぞれ対象時点と確認時点を持つ | 出典、対象年、最終確認、データなし |

`domestic` は輸送手段ではなく範囲、複合輸送は複数の区間を順番に通る経路として扱う。`coastal` と `maritime` は海運の範囲・サービス種別へ対応させる。既存IDを直ちに変える提案ではなく、移行時の対応表を先に作る。

新幹線を旅客だけに固定しない。JR東日本には新幹線を使った荷物輸送サービスがあるため、鉄道の種類と運ぶ対象を独立させ、裏付けのある区間にだけ貨物の意味を付ける。[JR東日本 はこビュンQuick](https://hakobyun-baggage.jreast.co.jp/guide/beginner_guide/train)

### 概念と関係

- 拠点：駅、貨物駅、空港、港、IC/JCT。出典元IDと内部の安定IDを対応させる。同名だけで結合しない。
- 区間：同一の物理路線に属する形状と端点。現在の道路区間・方向・接続点の定義を維持する。
- サービス：拠点間の実在する運行・就航上の接続。1サービスは複数の拠点・区間を順に参照でき、1区間を複数サービスが利用できる。
- 流動統計：対象期間、起終点、輸送手段、品目、単位、値を持つ。地域間流動は自動的に特定路線の通過量にはならない。
- 運行事象：出典が特定したサービスまたは区間に時点付きで関連付ける。地理的に近いだけで別路線へ転用しない。
- 複合経路：複数サービス・区間の順序付きのつながり。実際の乗継や積替えが確認できない接続は、実在する一貫輸送として扱わない。

分類・説明の責任はプロダクト、個々の事実の権威は各出典、正規化・更新・結合の責任はデータ実装に分ける。下記の名称は設計上の概念で、永続スキーマの確定ではない。

出典の管理単位はURLだけでなく、対象、役割、版、対象期間、取得日、公開・再配布条件、取得方式、更新間隔、地理的範囲、結合キー。1本の表示線でも形状・就航・量・運行状況で別の出典を持てるようにする。

## 一般向けの入り口

初期画面の主題は「あなたの地域は、どこにつながる？」。最初の操作は地域選択、または馴染みのある交通手段の選択。全国の路線を全部同じ強さで重ねない。

- 全国表示：主要ネットワークと主要拠点を見せる。新幹線など一つの手段を選ぶと、その線を強調する。
- 地域表示：地域に関わる路線・駅・空港・港と接続先を見せる。拡大に応じて詳細を出す。
- 選択後：「何を結ぶか」「何を運ぶか」「どんな役割か」を短く説明し、対象年・出典へ辿れるようにする。

興味を引く入口として、事実から作れる小さな問いを用意する。例：「トラックも船に乗る？」「新幹線は荷物も運ぶ？」「自分の地域につながる貨物駅はどこ？」。最初の二つは[さんふらわあの貨物輸送案内](https://www.sunflower.co.jp/cargo/service.html)と[JR東日本のサービス案内](https://hakobyun-baggage.jreast.co.jp/guide/beginner_guide/train)で根拠を確認できる。

「この道が止まると食料が何日で不足する」といった影響や、特定の商品の実際の配送経路は、別の根拠・モデルがなければ表示しない。最短経路を計算しただけでは実輸送経路と呼ばない。

## 文字が収まる画面構成

添付画像は生成した画面案で、実装済み画面ではない。現状は左ペインの見出しと説明が地図領域へ伸び、テーマ選択とテーマ名の列が重複している。文字を小さくするだけでは解消しない。

修正方針：

- ヘッダーは製品名、テーマの選択、メニューのみ。テーマ名を全て横に並べる列は削除する。
- 左ペインはデスクトップで320〜380pxを目安に可変幅。見出し「地域のつながりを見る」は2行まで自然に折り返し、説明は通常の文章として折り返す。高さを固定して隠さない。
- 「人の移動 / 物の輸送」と交通手段の選択は左ペイン内に配置する。交通手段は2列または縦一覧にし、長いラベルが地図へ侵入しない。
- 地図は独立したグリッド領域に置く。見出し、表、凡例を地図の上へ無理に流さない。
- 詳細な出典名・説明は開閉可能にする。提供元と対象年は短く常時表示する。
- 1280 / 1440 / 1680px幅と200%拡大で実ブラウザー確認。狭い画面ではペインを折りたたみ、本文や操作ラベルを縮小して押し込まない。

## 導入順と判断が必要な範囲

1. 分類と出典の対応を確定する。画面名は「交通・物流」を推奨。既存 `theme=logistics` と選択IDは互換性を維持する。
2. 高速道路・新幹線・旅客鉄道の全国ネットワークと、根拠を確認した貨物鉄道・航空・海運の接続を導入する。表示対象の網羅性を明示する。
3. 路線選択・地域選択と、根拠付きの短い説明を実装する。統計がある対象には同じ期間・単位の数値を加える。
4. 運行状況は、採用情報の許諾・取得・区間対応を確認できたものから既存の別レイヤーに追加する。

UIの方向と旅客を含める分類は本提案への判断対象。既存の地図エンジン、道路区間モデル、根拠検証、運行データの分離は維持する。採用出典の取込方式・更新処理や永続スキーマの追加は、出典ごとの具体案が決まってから設計する。今回、外部契約・自動取得・データ移行は行っていない。


## 2026-09-16 実装と検証

- 全国の高速道路・新幹線・旅客鉄道/軌道を国土数値情報2025年版から収録。航空6接続と海運6航路は事業者案内による抜粋。出典と加工条件は [データREADME](../../data/transport/README.md)。
- 交通・物流は左の読み取りパネルと独立した地図を持つ。5手段、地域、名称検索、用途、地図/一覧からの選択、出典と時点、モバイルの開閉、URL再表示を実装。
- 新旧分類を無理に同じイベント型へ統合せず、静的ネットワークを `TransportRoute` として明示。既存イベントID・道路provider・権利検証・MapLibreを維持。旧URLとデモへの入口を保持。
- 空港運用seedの「55分前」「次回更新60分」「official_public」を固定デモ表記へ修正。外部データ取得や契約の代替は行っていない。
- コメは上位5道県と全国比を先に提示。塗りの色は実数による10万トン刻みの5階級を用い、凡例と同じ定義を共有。選択は輪郭で示す。暗い基図、県内ラベル、全国が収まる初期表示を適用。
- デスクトップの地図はパネルの背後まで延びない領域に配置。通常ペイン380px、詳細表示時320pxとし、1280px時に詳細360pxと地図600pxを保つ。
- 1つの動作する縦の実装として、型・出典・生成物・表示・URL互換性をまとめて変更。データだけ/ボタンだけの並行デモには分割していない。

未導入：全国の航空・海運サービス完全収録、貨物専用鉄道、便数・輸送量、渋滞/運休/位置の自動更新、遅延予測。対象外を現在値やゼロで補わない。将来のデータ提供契約・取得基盤は別判断。

実画面、端末幅、操作、検証の証跡は [design-qa.md](../../design-qa.md)。commit、push、PR、deployはしていない。
